## 2026-05-13: Superpowers 流程不是自动触发的

**问题：**
用户期望每个任务自动走 superpowers 固定顺序流程，但实际上 superpowers 是按需匹配的 skill 系统。

**教训：**
- Superpowers 用 Skill 工具按需调用，不是强制顺序
- "每个任务按顺序执行" 是用户的期望，不是系统机制
- 必须在 CLAUDE.md 里明确触发条件，让 AI 自动判断何时调用

**解决方案：**
更新 CLAUDE.md 为"自动触发"模式：
- 创意/功能/复杂任务：先 brainstorming
- Bug修复：先 debugging
- 新代码：先 TDD
- 简单问题：直接回答

## SSH 隧道到云服务器（2026-05-26）

**用途**：从外网访问本地 Dashboard

**步骤**：
1. 确认公钥已添加到服务器 `/root/.ssh/authorized_keys`
2. 执行：`ssh -f -N -R 5188:localhost:5188 -o StrictHostKeyChecking=no -o ServerAliveInterval=60 root@123.56.13.231`
3. 手机访问：`http://123.56.13.231:5188`

**前提**：
- 云服务器 SSH 需允许 GatewayPorts（`/etc/ssh/sshd_config` 中 `GatewayPorts yes`）
- 公钥在 `/root/.ssh/authorized_keys`

**注意**：隧道是临时的，电脑关机/休眠则断开。

## 2026-06-02: 彩票系统开奖后无法自动更新的根因与解决方案

### 问题现象
开奖后（21:32:32）系统未能自动获取最新数据，2026153 期 pending

### 根因
1. cron 21:35 触发时，API 尚未发布开奖数据（开奖后约 2-3 分钟才发布）
2. 系统单点失败：每天仅 21:35 一次触发，无重试机制
3. API 超时后回退缓存，导致无法感知新数据

### 教训
- **单一时间点触发无法应对有延迟的外部系统**：当外部系统数据发布晚于触发时间，必须引入轮询机制
- **日志中的"API 最新"可能来自缓存而非真实 API**：需验证数据来源
- **Circuit Breaker 重置机制设计缺陷**：process-level breaker 每天只重置一次，不适合此场景

### 解决方案
新增独立监控进程 lottery_monitor.py：
- 21:34 启动（主 cron 前 1 分钟）
- 每 2 秒轮询 API 检查新期号
- 发现新数据立即写入缓存并退出
- 超时 120 秒自动退出

### 验证要点
1. 新进程不触发预测流程（仅更新缓存）
2. 锁文件完全独立（pipeline.lock vs monitor.lock）
3. 超时退出后无残留进程（flock + PID_FILE 清理）
4. 缓存写入具备幂等性（覆盖写入 + 期号变化检查）
