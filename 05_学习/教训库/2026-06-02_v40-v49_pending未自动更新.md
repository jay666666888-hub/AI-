# 教训库：v40-v49 pending 状态未自动更新

日期：2026-06-02

## 问题描述
开奖后 v40-v49 的预测记录仍显示 pending（actual=None），未自动更新。

## 根因分析

### 原因 1：v40-v49 元数据缺失
v40-v49 的 metadata 文件位于 `predictors/retired/` 而非 `predictors/active/`：
- `PredictorRegistry.scan()` 只扫描 `predictors/active/`
- `predictors/retired/` 仅被 index_generator 扫描用于生成 retired 列表
- 导致 `verify_prediction()` 无法找到 v40-v49 的 metadata

### 原因 2：verify_prediction 失败
v40-v49 metadata 缺少 `play_type` 字段，导致 verify 时报错：
```
Version 'v40' metadata 缺少 play_type 字段
```

### 验证结果
- API 数据正常（366 条 2026 记录）
- get_all_records 正常（885 条总记录）
- Dashboard 缓存正常（30s TTL）
- 活跃版本验证正常（v12, v23 等正确更新）
- 问题仅限 v40-v49（10 条记录 pending）

## 解决方案

### 方案 1：手动修复（已执行）
直接修改 aggregated_live.jsonl，为 v40-v49 的 2026153 预测补充 actual/hit/status

### 方案 2：修复元数据（根本解决）
将 v40-v49 metadata 放入 `predictors/active/v40/metadata.json` 并补全 play_type

## 教训
1. retired 目录的版本不会被 PredictorRegistry 动态发现
2. metadata 必须包含 play_type 字段
3. 多目录结构导致 registry 扫描不一致

## 预防措施
1. 统一使用 `predictors/active/` 存放所有活跃版本
2. 创建 retired 软链接或统一版本发现机制
3. Dashboard 应使用 API 数据源而非聚合文件
